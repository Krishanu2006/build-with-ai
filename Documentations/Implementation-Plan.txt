# CivicSignal — Multilingual Civic Intelligence Platform (MVP)

A multilingual civic intelligence platform that transforms fragmented citizen voice and text requests into structured, geographically contextualized, explainable evidence for public-sector planning.

## User Review Required

> [!IMPORTANT]
> **No Backend Required for v1**: The app will run entirely in the browser with an in-memory and `localStorage`-backed service layer simulating the full asynchronous pipeline (`POST /api/requests`, `GET /api/requests/:id`, `GET /api/hotspots`, `GET /api/hotspots/:id/evidence`, etc.). New citizen requests submitted through the UI will be saved in local storage, processed asynchronously, and immediately reflected on the live dashboard and map.

> [!NOTE]
> **Voice Recording in Browser**: The voice intake uses the standard HTML5 `MediaRecorder` API. In environments where microphone permission is denied or unsupported, the interface immediately and gracefully offers the text intake option without crashing, strictly satisfying AC-004.

## Detailed Screen Specifications

### 1. Citizen Request Interface (`SCR-001` - `/submit`)
- **Mode Toggle**: Segmented control between "Speak" and "Type".
- **Text Mode**: Textarea for free-form citizen description.
- **Voice Mode**: Accessible audio recorder leveraging the Web `MediaRecorder` API:
  - Start recording, elapsed time display, audio waveform/level indicator, stop, preview playback, and re-record.
  - Graceful fallback: If microphone permission is denied, shows clear explanatory alert and switches to text mode without page reload (AC-004).
- **Optional Details**:
  - Collapsible disclosure for "Add location or language (optional)".
  - Language selector (Auto-detect, English, Kannada, Hindi).
  - Location input with text hint and dropdown of reference areas.
- **Submit Flow**:
  - Validates input, shows "Sending..." busy spinner on button, saves request in `mockDataStore`.
  - Begins simulated pipeline (`received` → `transcribed` → `extracted` → `geolocated`), immediately navigating to `SCR-002`.

### 2. Submission Confirmation & Status (`SCR-002` - `/submit/:requestId`)
- **Status Banner**: Confirms receipt with monospace copyable ID.
- **Progress Stepper**: Displays pipeline stages in real-time.
- **"What we understood" Card**:
  - Displays transcript (with "Machine transcript" tag for voice requests).
  - Detected language, extracted category, issue summary, severity, and resolved geographic area.
  - Honest failure states: If extraction/geocoding is unresolved, plainly states so without fabricating guesses (AC-006, AC-009).
- **Action Buttons**: "Submit another request" and "View on Dashboard".

### 3. Policymaker Dashboard (`SCR-003` - `/dashboard`)
- **Provenance Strip**: Prominently notes that displayed data is synthetic demo data (DG-03, DC-20).
- **FilterBar**:
  - Filters by Category (Water Supply, Roads & Transport, Sanitation, Healthcare, Electricity), Severity (High, Medium, Low), Area, and Time window.
  - Shows live matching hotspot count and "Clear filters" action. Filter selections persist in the URL query string.
- **Dual Map & Accessible List Views**:
  - **Leaflet Map**: Renders Bengaluru Urban areas. GeoJSON polygons are shaded according to the 5-step intensity ramp (`#E3ECF4` to `#2D6193`). Hovering shows summary tooltip; clicking an area selects the hotspot and highlights the list row. Centroid marker fallback for areas lacking geometry.
  - **Map Legend**: Explains the metric ("Citizen requests per area") and the 5-step threshold scale.
  - **Hotspot List**: Accessible keyboard-navigable ranked list (`FC-010`). Each item displays rank, area name, total requests, dominant category badge, and mini severity indicator.
  - Selecting an area on either map or list docks the **Hotspot Detail Panel** (`SCR-004`).

### 4. Hotspot Detail Panel (`SCR-004` - `/dashboard/hotspot/:hotspotId`)
- Docks alongside the map on desktop; slides in as an overlay sheet on tablet and mobile.
- Follows the required fixed reading order from [Design.md](file:///d:/Desktop/Build-With-AI/Design.md) §7.3–§7.5:
  1. **"Why this region?" Evidence Breakdown (`FC-012`)**:
     - Explicit signal table: Total requests, category share, high severity count, density score, population denominator.
     - Recharts bar charts for category distribution and severity breakdown.
     - **Signals Not Available Box**: Explicitly lists missing signals (e.g. "Public Investment: No verified data source available (TBD / requires verification)") — never omitted or replaced with zero (AC-013, AC-015).
     - Method line: Explains the deterministic aggregation rule used.
  2. **Contributing Citizen Requests (`FC-015`)**:
     - Expandable list of underlying citizen requests.
     - Displays original text (in English, Kannada, or Hindi), language badge, category/severity badges, machine transcript indicator, and an instant "Show translation" toggle.
  3. **Contextual Indicators (`FC-013`)**:
     - Demographics (Population, Density, Literacy) with Provenance pills (`Census 2011`, `Public`, `Synthetic`).
     - Infrastructure gaps (Piped water coverage, PHC access).
     - Investment tracking with prominent `TBD / requires verification` warning tag.
  4. **Candidate Interventions (`FC-014`)**:
     - Non-dismissible advisory banner: "Suggestions — requires human decision. The platform does not make policy decisions."
     - Suggestion cards with rationale and chips linking back to motivating evidence signals.

### 5. Method & Data Provenance (`SCR-005` - `/method`)
- Formal documentation page explaining:
  - System mission and decision-support boundaries (DG-04).
  - Data sources table with provenance, vintage, and verification status.
  - Deterministic aggregation algorithms vs. AI NLP extraction.
  - Known limitations and accessibility commitments.
